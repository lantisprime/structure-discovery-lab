## Findings

**1. SHOULD — `src/replay_check.py`, `restore()` — restore crashes exactly when the script is destructive.**
If the script removes a declared output's parent directory, `open(path, "wb")` raises `FileNotFoundError` mid-restore: the function exits with an exception instead of the `ERROR` dict, and the files not yet restored stay damaged. Concrete input: a generator containing `shutil.rmtree("results"); sys.exit(1)` — `replay()` propagates `FileNotFoundError` from `restore`, and `results/out.json` is not put back. In `source_replay`/`run_check_at` the worktree is discarded so the blast radius is contained, but the checker's core promise ("puts every byte back") fails precisely in the failure mode it exists for, and a manual CLI run in a real checkout would leave it dirty. Fix: `os.makedirs(os.path.dirname(path), exist_ok=True)` before writing, and wrap the per-file restore loop so one failure doesn't skip the rest.

**2. SHOULD — `src/replay_check.py`, `restore()`/`replay()` — three restore gaps contradict the docstring.**
(a) A file dirty *before* the run that the script also touches (`dirty_before ∩ dirty_after`) is left with the post-run bytes, not its pre-run bytes — in the healer's worktree that can silently alter a proposer-written side-effect file after the gate "passed" it. (b) An untracked file the script *deletes* leaves no trace in `dirty_after`, so it is never restored. Concrete input: checkout with untracked `notes.tmp`; script does `os.remove("notes.tmp")`; after the check, `notes.tmp` is gone. (c) Untracked directories created by the script are left behind as empty dirs. Fix: snapshot bytes of any dirty-before path the run touches, or narrow the docstring to "declared outputs and tracked side effects"; at minimum stop claiming "restores every byte it touches" (docs/AGENT_WORKFLOW.md repeats the claim).

**3. SHOULD — `src/lab_tier.py`, `tally()`/`proven()` — a tier can be "proven" by rolls against a stale definition.**
Rolls are keyed only by (eval, tier); the `definition sha256` sitting in every `agent.txt` is read but never compared. Concrete input: edit the `lab-proposer` prompt (new definition sha), keep the 3 old haiku PASS rolls per eval inside the 5-roll window — `--recommend` recommends haiku for an agent those rolls never ran. The same applies to a changed eval prompt. Impact is bounded (the output is only a `tier` lesson; the frontmatter edit stays an owner-visible PR), but the lesson will be injected into future briefs as if it were evidence about the current definition. Fix: count only rolls whose agent definition sha matches the current frontmatter sha (it's already on the line), or exclude rolls the ledger marks `STALE_EVAL`.

**4. SHOULD — `src/lab_gate.py`, `scope_reasons()` — REQ-3's "deleted = rewrite" only holds if `results_modified` includes deletions.**
The frozen-results clause scans `diff["results_modified"]` only; the `deleted` list is examined only for test files. The test fakes a diff where the deleted output appears in *both* lists, so the enforcement is proven against the fake, not against `GH.diff`'s real shape. Concrete failing input (if the real diff classifies deletions only under `deleted`): a PR whose whole change is deleting `results/meta_uniformity.json` — `scope_reasons` returns `[]`. Fix: add `why += [f"frozen result ... deleted: {p}" for p in diff.get("deleted", []) if p.startswith("results/")]` (no exemption — a deleted declared output is always a rewrite), or assert in a test against the real `GH.diff` that deletions land in `results_modified`.

**5. NIT — `src/replay_check.py`, `git_status()` — porcelain parsing mangles renames and quoted paths.**
`l[3:]` on `R  old -> new` yields the literal string `old -> new`, and paths with spaces/quotes come back C-quoted, so such a side-effect file would be "restored" to the wrong name or missed. No lab path hits this today. Fix: `git status --porcelain -z` and split on NUL.

**6. NIT — `src/lab_tier.py`, `recommend()` — cheaper-first priority can downgrade a failing agent.**
The cheaper-proven rule is evaluated before the current-fails rule, so "current fails on P-1" + "cheaper tier proven" recommends the cheaper tier. The plan's wording ("a proven cheaper tier, *or* a proven higher tier when the current fails") leaves the tie-break unspecified and the chosen order is defensible (a genuinely proven cheaper tier is proven), but it should be a deliberate, documented choice — one line in the docstring.

**7. NIT — `src/lab_tier.py`, `run()` — dedup compares only the latest `tier` lesson per artifact.**
Oscillating evidence (recommend A, then B, then A again) re-appends A. Harmless for an append-only ledger; noting it.

**8. NIT — `src/outcome_collect.py`, `DetachedWorktree` — small leaks.**
The `mkdtemp` dir leaks if `__enter__` is never reached; `__exit__` doesn't tolerate an already-removed worktree, so a `git()` failure there can mask the original exception from the `with` body. Fix: create the dir in `__enter__`, wrap the removals in try/except.

**9. NIT — `src/outcome_attribute.py`, `check_command()` — `list(detail.get("outputs"))` relies on `outputs` being a dict keyed by path.**
Works today (keys are the rel paths, in declaration order), but a future list-shaped payload silently produces garbage argv. A one-line assert/normalize would make it robust.

**10. NIT — `src/lab_gate.py`, `route_unhealable()` — reimplements the attempt count inline.**
`heals = [...]` duplicates `heal_attempts()`'s selection logic; if the two ever drift, the PR-path cap and the no-PR-path cap disagree. Reuse `heal_attempts(rows, key, commit)` and keep the list only for `last`.

## Answers to the questions

- **Q1:** Findings 1, 2, 4 carry concrete failing inputs. Nothing else found that fails on a realistic input; the core flows (replay source, bisect-by-absolute-checker, scope exemption symmetry, immediate routing, lessons hash-linking, roll windowing) are correct as far as the diff lets me verify.
- **Q2:** No guardrail is weakened. The results/ exemption is (a) scoped to the *defect's own* artifact via exact script match in `replay_outputs`, so a proposal cannot reach another artifact's outputs; (b) mirrored between healer (`scope_violations`) and gate (`scope_reasons`); (c) deletion-safe in the healer (`os.path.exists` filter) and in the gate modulo finding 4. Append-only is untouched (`lab_tier` goes through `LL.append_lessons`); the self-approval bar and different-family verifier are unchanged; the OWNER-RESERVED line-check is strictly *stricter* than the old substring match. PR #34's routing is evidence the machinery works as intended.
- **Q3:** Both deviations are sound. Checkout-copy comparison is the only semantics that makes the healer's uncommitted regeneration the candidate, and in every loop invocation (detached HEAD worktree, probe worktree, PR-head worktree) the checkout copy *is* the committed copy. The one case it "breaks": a human running `replay_check.py` manually in a dirty checkout compares against dirty bytes — but that is the documented contract. The absolute checker path is what makes bisection over pre-checker commits possible; its only cost is that checker behavior drift over time makes old bisections not bit-reproducible — acceptable for an attribution heuristic.
- **Q4:** A single lucky roll cannot produce a recommendation — `proven` requires ≥3 rolls, all PASS, on *every* eval of the agent. A stale old roll *can*: windowing is by recency within (eval, tier), not by definition freshness — that is finding 3.
- **Q5:** Yes. A deliberate `OWNER-RESERVED` stop is information, not a failed attempt; retrying up to the cap would re-derive the same conclusion at dispatch cost (the brief is near-deterministic) and delay the only actor who can act. The notes travel with the issue, the route is idempotent, the healer skips routed occurrences, and the attempt-cap route remains for everything else. This matches the PR-path behavior (PR #34 → issue #35) that already proved itself.
- **Q6:** I would merge after fixing findings 1 and 4 (small, mechanical) and deciding on 3; 2/5–10 can be follow-ups.
