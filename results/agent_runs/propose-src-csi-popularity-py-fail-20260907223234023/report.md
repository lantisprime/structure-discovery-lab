# HEAL_NOTES.md

## Defect
`src/csi_popularity.py --verify` failed with `VERIFY MISMATCH: regenerated bytes
differ from results/csi_popularity_2026-09-06.json` (ledger row
`verify_entrypoint|src/csi_popularity.py|FAIL`, attributed to commit a03a518).

## Root cause
Commit a03a518 changed the script's default `--seed` from `20260906` to
`20260907`. The frozen result `results/csi_popularity_2026-09-06.json` was
generated (and its `_meta.seed` field records) `20260906`, and `--run-date`
still defaults to `2026-09-06`. `--verify` regenerates the payload using the
current defaults and byte-compares it against that frozen file; with the
seed drifted one day ahead of the run-date, every seeded stream (the H0 null
trial, the stratified permutations, the power simulation, and the per-pool
uniform reference draws) diverges from the frozen bytes, so the compare
fails deterministically. This was a planted single-line defect for the
healing loop (commit message: "plant: csi_popularity default seed drifts
from the frozen result").

## Fix
Reverted the one-line drift in `src/csi_popularity.py`:
`ap.add_argument("--seed", type=int, default=20260907)` →
`default=20260906`, restoring the seed that matches both the frozen
result's `_meta.seed` (`20260906`, confirmed by inspecting
`results/csi_popularity_2026-09-06.json`) and the `--run-date` default
(`2026-09-06`). No other lines changed; this is the smallest change that
restores byte-identity with the frozen, immutable result file rather than
weakening or rewriting the verify check itself.
