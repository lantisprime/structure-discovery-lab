# HEAL_NOTES.md

## Root cause
Commit `a03a518` ("plant: csi_popularity default seed drifts from the frozen
result") changed the `--seed` argparse default in `src/csi_popularity.py` from
`20260906` to `20260907`. `results/csi_popularity_2026-09-06.json` (the frozen
result the `--verify` entrypoint byte-compares against) was generated with
`"seed": 20260906`. Because the default seed no longer matched the seed baked
into the frozen result, `--verify` regenerated the report with a different RNG
stream, producing different bytes and failing with `VERIFY MISMATCH`.

## What I changed and why
Reverted the single line in `src/csi_popularity.py`:
```
-    ap.add_argument("--seed", type=int, default=20260907)
+    ap.add_argument("--seed", type=int, default=20260906)
```
This is the smallest change that restores the default seed to the value the
frozen result was generated with, so `--verify` regenerates the same bytes for
the right reason (matching seed → matching deterministic RNG stream), rather
than by weakening the byte-comparison check itself. No other file references
or depends on the drifted default; the frozen result, ledger rows, and
`docs/kb/conscious-selection-popularity.md` were not touched.
